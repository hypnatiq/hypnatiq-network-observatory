# Privacy, Safety, and Limitations

## Privacy

- Local evidence should remain local unless the user explicitly selects an online lookup.
- Each provider view should state what data would be sent, why it is needed, and what account limits apply.
- Screenshots and examples must use controlled test data and must not expose personal browsing or private infrastructure.
- Telemetry, notifications, and updates should remain separately configurable.

## Response safety

- Read-only observation should be the default.
- A proposed firewall change is not an applied change.
- An applied change is not complete until the result is verified.
- Every consequential response needs a recovery path.
- Unsupported authority or incomplete prerequisites must be reported directly.

## Limitations

- Process attribution may be incomplete when Windows cannot identify the source.
- Encrypted traffic limits content visibility.
- Reputation data can be stale, incomplete, or wrong.
- A destination can be legitimate in one context and suspicious in another.
- A clean antivirus result does not prove that a file is safe.
- Interface screenshots show a development build and do not prove installed behavior.
